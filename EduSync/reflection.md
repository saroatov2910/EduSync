# Personal Reflection - Code Review Assignment

## Learning Process
Creating intentional violations of coding standards and then correcting them provided valuable hands-on experience with the importance of consistent naming conventions in software development. This exercise highlighted how easy it is to introduce inconsistencies, especially when working quickly or under pressure.

## Challenges Encountered
The main challenge was maintaining awareness of different naming conventions across various contexts - PascalCase for React components, camelCase for functions and variables, and lowercase-hyphen for CSS classes. I found myself naturally gravitating toward inconsistent patterns, particularly when switching between TypeScript and CSS files.

## Key Insights
This assignment reinforced that coding standards are not merely aesthetic preferences but essential tools for code maintainability and team collaboration. Well-structured naming conventions significantly improve code readability and make it easier for new developers to understand and contribute to a project.

## Perspective Shift
Before this exercise, I viewed coding standards as helpful guidelines rather than critical requirements. Now I recognize them as fundamental to professional software development, where the investment in learning and applying standards pays dividends in long-term code maintenance and team productivity.
